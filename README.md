# Video Narration & Subtitles Skill

一个面向产品演示、能力演示和客户端操作录屏的 Codex Skill。它指导 Agent 将无声录屏或原声不适合直接使用的视频，整理为带有简洁中文解说、自然配音和清晰字幕的可交付成片。

这个 Skill 的重点不是逐字复述屏幕，而是讲清楚一条完整的能力链路：用户做了什么、产品识别或调用了什么、Skill 执行了什么，以及最终交付了什么。

## 能力概览

- 分析视频时长、分辨率、音轨和关键画面
- 将操作流程提炼为 5-8 段简洁中文解说
- 分开维护字幕文本与 TTS 文本，改善英文术语和多音字的朗读效果
- 使用 Microsoft Edge TTS 生成自然中文配音
- 生成黑底白字、自动换行、位置稳定的字幕图层
- 使用 FFmpeg 合成 H.264/AAC MP4 成片
- 同时交付成片、SRT 字幕和独立配音音频
- 抽查开头、中段和结尾，并验证音视频流与时长

## 适用场景

- 产品功能演示录屏
- AI Agent / Skill 调用链路演示
- SaaS 或企业软件操作讲解
- 无声 Demo 视频后期
- 原始环境音不适合公开传播的视频

它不适合需要逐字转写、影视级混音、多角色对白或复杂动态字幕包装的项目。这些场景通常需要专门的转写、音频工程或非线性剪辑工作流。

## 工作方式

```text
输入录屏
   |
   v
检查媒体信息与关键帧
   |
   v
提炼 5-8 段能力导向文案
   |
   v
用户确认文案
   |
   +-----------> Edge TTS 分段配音 ---------+
   |                                         |
   +-----------> Pillow 字幕图层 ------------+--> FFmpeg 合成
                                             |
                                             v
                                  MP4 + SRT + 配音音频
```

Skill 要求先确认文案再进入渲染阶段，避免耗时的 TTS 和视频编码建立在错误叙事上。如果原视频包含需要保留的有效音轨，也会先确认混音比例。

## 安装

### 安装到 Codex

```bash
git clone https://github.com/Rockelbel/video-narration-subtitles.git \
  ~/.codex/skills/video-narration-subtitles
```

重新启动 Codex 或开启新会话，使 Skill 被重新发现。

也可以将仓库放入其他支持 `SKILL.md` 的 Agent 技能目录中；具体目录和发现机制取决于对应客户端。

## 运行依赖

该 Skill 描述了一套由 Agent 执行的工作流，本仓库不包含独立的视频编辑 CLI。实际执行环境需要：

- [FFmpeg](https://ffmpeg.org/)：媒体探测、音频混合、字幕叠加和最终编码
- [edge-tts](https://github.com/rany2/edge-tts)：中文语音合成
- [Pillow](https://python-pillow.org/)：生成 RGBA 字幕图层
- PingFang 字体：默认字幕字体，macOS 系统自带
- Python 3：运行 `edge-tts` 和 Pillow

Python 依赖可安装为：

```bash
python3 -m pip install edge-tts Pillow
```

请自行准备可用的 `ffmpeg` 和 `ffprobe`。Skill 明确不要求 Agent 使用 Homebrew 安装依赖，以免未经确认修改用户的系统环境。

> 当前字幕排版偏好针对 macOS 和 PingFang 优化。在 Linux 或 Windows 上使用时，应让 Agent选择可用的中文字体，并在成片前重新检查字形、换行和基线。

## 使用示例

在 Codex 中直接描述视频和目标即可：

```text
请使用 $video-narration-subtitles，给 demo.mp4 制作简洁中文解说和字幕。
这是一个出差规划 Skill 的演示，重点讲清用户需求、行程查询、合规筛选和申请草稿生成。
```

第一阶段会得到待确认的分段文案。确认后，可继续要求：

```text
文案可以，继续生成配音、字幕和最终成片。
```

典型时间轴数据会同时维护画面字幕和朗读文本：

```json
[
  {
    "start": 0.0,
    "end": 5.8,
    "subtitle": "用户输入出差需求，系统识别并调用行程规划 Skill",
    "tts_text": "用户输入出差需求，系统识别并调用行程规划技能"
  }
]
```

这样可以在画面中保留产品术语 `Skill`，同时让语音自然地朗读为“技能”。

## 默认视听规范

### 解说

- 默认使用 `zh-CN-XiaoxiaoNeural`
- 默认语速为 `+10%`
- 只讲行为、能力和结果，不逐项念航班号、价格或界面字段
- 必要时改写容易误读的多音字，例如将“差标”写为“出差标准”
- 每段配音应在下一段开始前结束

### 字幕

- 纯黑不透明圆角背景
- 纯白文字，小而清晰
- 根据可用宽度自动换行
- 文字在背景框内垂直居中
- 位于画面底部，同时避开输入框、操作栏和关键结果

### 输出

- H.264 视频与 AAC 音频封装的 MP4
- 独立 SRT 字幕
- 独立配音音频
- 经 `ffprobe` 验证的媒体流和时长

## 设计原则

### 讲能力，不念屏幕

好的演示解说应该帮助观众理解因果关系。与其逐项念出所有界面内容，不如说明系统如何理解意图、调用能力、处理约束并产出结果。

### 文案与朗读分离

适合展示的术语未必适合直接交给 TTS。通过独立的 `tts_text`，可以保留字幕的产品表达，同时修正英文、缩写和多音字的读法。

### 先确认，再渲染

视频编码和语音合成都有成本。先确认分段文案与时间轴，可以显著减少返工，并让用户在最终合成前控制叙事重点。

### 用抽查守住交付质量

至少检查开头、中段和结尾，确保字幕没有遮挡关键操作、文字没有溢出、术语显示正确，并确认音画总时长一致。

## 隐私与文件管理

录屏经常包含账号、联系人、企业数据或内部界面。公开分享前请检查源视频、关键帧、字幕和最终成片，必要时先做裁剪或脱敏。

仓库默认忽略常见视频、音频、字幕和临时渲染目录，避免在开发 Skill 时误提交用户素材。需要提交示例媒体时，请使用明确的 `git add -f`，并确认拥有公开授权。
